================================================================================
  BoneVisQA — Frontend Setup Guide (Next.js)
================================================================================

This document explains how to install and run the BoneVisQA web application
locally. All commands below assume you are in the Next.js application root
(the folder that contains package.json — typically named "web").


--------------------------------------------------------------------------------
1. ENVIRONMENT REQUIREMENTS
--------------------------------------------------------------------------------

Operating system
  Windows, macOS, or Linux

Node.js
  Version 20.x or later (LTS recommended)
  Download: https://nodejs.org/

Package manager
  npm (included with Node.js) — this project uses npm and ships with
  package-lock.json. Use npm for all install and run commands below.

  Optional: yarn or pnpm may work, but npm is the supported and tested
  package manager for this submission.

Other prerequisites (for full functionality)
  - A running BoneVisQA backend API (.NET 8) reachable from your machine
    (default local origin: http://localhost:5046 or https://localhost:5047)
  - Valid user accounts in the backend database (e.g. Student, Lecturer)
  - Optional: Supabase project credentials (storage / auth integration)
  - Optional: Google OAuth Client ID (Sign in with Google button)

Verify your setup:

  node -v          # should print v20.x or higher
  npm -v           # should print 10.x or higher (bundled with Node 20)


--------------------------------------------------------------------------------
2. ENVIRONMENT VARIABLES
--------------------------------------------------------------------------------

Create a local environment file before starting the dev server.

Step A — Copy the example file:

  cp .env.example .env.local

  On Windows (Command Prompt):

  copy .env.example .env.local

Step B — Edit .env.local and fill in the values below.

  --------------------------------------------------------------------------
  .env.local TEMPLATE (placeholders — replace with your values)
  --------------------------------------------------------------------------

  # Do not commit this file to version control.

  BROWSER=none
  NODE_ENV=development

  # Required: Backend API origin ONLY (no /api path suffix).
  # Axios client appends paths such as /api/student/...
  # Examples:
  #   http://localhost:5046
  #   https://localhost:5047
  NEXT_PUBLIC_API_URL=http://localhost:5046

  # Optional: Supabase (image storage and related features)
  NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
  NEXT_PUBLIC_SUPABASE_ANON_KEY=your-supabase-anon-key

  # Optional: Google Sign-In (OAuth 2.0 Web Client ID)
  # Add http://localhost:3000 to Authorized JavaScript origins in Google Cloud.
  NEXT_PUBLIC_GOOGLE_CLIENT_ID=your-google-client-id.apps.googleusercontent.com

  # Optional: Verbose SignalR connection logs (debugging only)
  # NEXT_PUBLIC_SIGNALR_VERBOSE=true

  # Optional: Legacy fallback for expert case image URLs (defaults to localhost:5046)
  # NEXT_PUBLIC_BACKEND_URL=http://localhost:5046

  --------------------------------------------------------------------------

Variable reference:

  NEXT_PUBLIC_API_URL
    Primary backend base URL. Must match the running .NET API host and port.
    Do NOT include a trailing /api segment.

  NEXT_PUBLIC_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_ANON_KEY
    Supabase project URL and anonymous key. Leave blank if not using Supabase
    storage in your evaluation environment.

  NEXT_PUBLIC_GOOGLE_CLIENT_ID
    Enables the "Sign in with Google" button on the auth page. If unset, the
    button is hidden and email/password login still works.

  NEXT_PUBLIC_SIGNALR_VERBOSE
    Set to "true" to print detailed @microsoft/signalr logs in the browser
    console (useful when debugging real-time notifications).

Notes:
  - Variables prefixed with NEXT_PUBLIC_ are exposed to the browser.
  - After changing .env.local, restart the dev server (npm run dev).
  - A reference copy of all keys is kept in .env.example in this folder.


--------------------------------------------------------------------------------
3. INSTALLATION STEPS
--------------------------------------------------------------------------------

1. Open a terminal and navigate to the Next.js project root:

     cd path/to/BoneVisQA_FE/web

2. Install dependencies:

     npm install

   This reads package.json and package-lock.json and downloads all required
   packages into node_modules/. First install may take several minutes
   depending on network speed.

3. Configure environment variables (see Section 2):

     cp .env.example .env.local
     # then edit .env.local with your API URL and optional keys

4. (Recommended) Confirm the backend API is running before starting the UI.


--------------------------------------------------------------------------------
4. RUNNING THE APPLICATION
--------------------------------------------------------------------------------

Development mode (hot reload):

  npm run dev

Expected output:
  - Next.js compiles the application
  - Local URL: http://localhost:3000

Open http://localhost:3000 in a web browser.

Typical first-time flow:
  1. Ensure NEXT_PUBLIC_API_URL points to your running backend
  2. Open http://localhost:3000
  3. Sign in at /auth/sign-in with a valid account

Other npm scripts:

  npm run lint       Lint source files (ESLint)
  npm run build      Production build
  npm run start      Serve production build (run build first)
  npm run dev:open   Start dev server (Windows helper to open browser)

Production preview (optional):

  npm run build
  npm run start

  Then open http://localhost:3000 (same default port unless PORT is set).

Troubleshooting quick checks:
  - API errors / 404: verify NEXT_PUBLIC_API_URL (no /api suffix)
  - Blank auth or CORS errors: backend must allow http://localhost:3000
  - SignalR warnings: ensure API hub is mapped; set NEXT_PUBLIC_SIGNALR_VERBOSE=true
  - Google sign-in disabled: set NEXT_PUBLIC_GOOGLE_CLIENT_ID or use email login


--------------------------------------------------------------------------------
5. ARCHITECTURE OVERVIEW (TECH STACK)
--------------------------------------------------------------------------------

BoneVisQA Frontend is a role-based medical education web app (Student,
Lecturer, Expert, Admin) built with modern React tooling.

Framework & language
  - Next.js 16 (App Router) — file-based routing under src/app/
  - React 19
  - TypeScript

UI & styling
  - shadcn/ui (New York style) — reusable components in src/components/ui/
    built on Radix UI primitives and styled with Tailwind CSS v4
  - Lucide React icons, Framer Motion for motion

Client state
  - Zustand — lightweight immutable-friendly stores for client session state
    (e.g. Visual QA workspace: sessionId, preview image, chat turns) with
    optional persist middleware
  - TanStack Query (React Query) — server state, caching, and data fetching

Data & integration
  - Axios HTTP client (src/lib/api/) with JWT interceptors and RFC 7807 error
    handling; connects to the .NET 8 REST API via NEXT_PUBLIC_API_URL
  - SignalR (@microsoft/signalr) for real-time notifications
  - Supabase client for storage-related features when configured
  - react-hook-form + Zod for form validation

High-level folder layout:

  src/app/           Route pages by role (student, lecturer, expert, admin, auth)
  src/features/    Domain modules (visual-qa, auth, lecturer, admin, …)
  src/components/  Shared UI (shell, chat, viewers, layouts)
  src/lib/         API clients, utilities, Supabase helpers

The frontend is a standalone SPA-style Next.js app; it requires the separate
BoneVisQA backend API to be running for authentication, cases, Visual QA,
quizzes, and admin operations.
